# 0007. Table conventions: UUID keys, timestamps, varchar enums, integer cents, indexed foreign keys

- **Status:** accepted
- **Date:** 2026-10-20

Every table follows the same conventions, set with the first migration (#24) so later tables
(#108 and on) do not each pick their own:

- **Keys:** `id` is a UUID primary key generated by Postgres (`gen_random_uuid()`, built into
  PG 16). Ids appear in URLs and logs, so they must not be guessable or reveal volumes.
- **Timestamps:** `created_at` and `updated_at` are `timestamptz NOT NULL DEFAULT now()`;
  SQLAlchemy also sets `updated_at` on every ORM update. Both come from
  `app.db.IdTimestampsMixin`, which every model uses.
- **Enums:** `app.db.str_enum()` stores the lowercase value in a `varchar(32)` plus a CHECK named
  `ck_<table>_<enum name>`, not a native Postgres enum. Adding a value replaces the CHECK in a
  migration; it never needs `ALTER TYPE ... ADD VALUE`, whose new value cannot be used in the
  transaction that adds it, and a native enum value can never be dropped.
- **Money:** integer `*_cents` columns (USD) with a `CHECK (<col> >= 0)`. Never `Float` or
  `Numeric`. A test walks `Base.metadata` and fails on any other type.
- **Foreign keys:** every foreign key column has a btree index (a UNIQUE constraint's index
  counts). No `ON DELETE CASCADE`: history and money must never vanish with a parent row.
- **Names:** constraints and indexes are named by `app.db.NAMING_CONVENTION`, so downgrades and
  later migrations can address them by name.

## Consequences

- In a migration, write enum columns as `sa.String(32)` with one explicit `sa.CheckConstraint`
  named `op.f("ck_<table>_<enum name>")`. Autogenerate renders `sa.Enum(...)` and the CHECK
  twice; with the naming convention that creates duplicate constraints.
- Autogenerate does not compare CHECK constraints. `tests/test_schema_core.py` compares every
  constraint and index name in the test database with the models instead.
- Deleting a user or another parent row with history needs an explicit decision (status
  change or anonymization), not a cascade.
